# 推荐系统说明

> 本文档说明志愿推荐的核心算法、当前已知的严重问题、以及修复方案。

---

## 一、算法骨架（一句话）

输入「省份 + 位次 + 选科」→ 预测每个 (学校, 专业) 的录取概率 → 按概率分冲/稳/保三档 → 每档内按综合质量排序 → 输出 96 所。

---

## 二、核心步骤

### 1. 数据过滤

- **SQL 层**：排除提前批、艺术、专项、预科、蒙授、民航飞行；非低位次考生排除专科/高职
- **选科硬过滤**：3+1+2 / 3+3 / 旧高考 三种模式分别匹配 `subject_must` 和 `subject_any_of`

### 2. 概率预测（`predict_admission`）

```
历史位次 → 跨年人口归一化 → 指数加权平均（近年权重 [2.0,1.4,1.0,0.7,0.5]）
→ 贝叶斯平滑（小样本向"同校均值"收缩，k=2）
→ Sigmoid 概率（×9 经验系数）
→ P0 校准（19.2 万条训练的分段线性校准器，ECE 0.028）
→ 高波动收缩（CV>0.20 时概率向 50% 收）
→ 缩招/扩招惩罚（缩招 50%+ 标记"数据可靠性极低"）
```

### 3. 分桶（gap_rate）

`gap_rate = (avg_min_rank_3yr - 学生位次) / 学生位次`

| 桶 | 范围 | 含义 |
|---|---|---|
| 冲 | [-0.20, -0.10) | 学校比学生难 10–20% |
| 稳 | [-0.10, +0.10] | ±10%，主力区间 |
| 保 | (+0.10, +0.40] | 学校比学生容易 10–40% |
| 丢弃 | < -0.20 或 > 0.40 | 超出范围 |

### 4. 排序与截断

- 每所学校同桶最多 5 个专业（`_SCHOOL_CAP = 5`）
- 冲 25 + 稳 46 + 保 25 = 96
- 若总数 < 30，自动补"参考"标注

### 5. 冷门挖掘（hidden_gem）

`gem_score = 冷门类型 × 0.55 + 学校质量 × 0.30 + 机会窗口 × 0.15`

五种冷门类型：A. 城市冷专业强 / B. 名字冷出路热 / C. 今年冷明年热（小年） / D. 学科强排名低 / E. 满意度高位次未涨

## 三、已知严重问题：保底学校过少

### 现象

浙江 480 分（位次 194,000）→ 保区仅 **1 所**（浙江水利水电学院·国际商务），期望看到 460–470 分档的保底学校。

### 根因

**贝叶斯平滑反向污染**：当一所学校有"少数冷门低分专业 + 多数热门正常专业"时，"同校均值先验"偏向"难"。冷门专业被平滑后位次被错误拉高，从保区掉进稳区。

**实测案例**：

| 学校·专业 | 去年实际分 | 平滑后均位 | 真实 gap | 最终 gap | 归桶 |
|---|---|---|---|---|---|
| 温州商学院·税收学 | **451** | 186k | **+0.09（保）** | **-0.038** | ❌ **稳区** |
| 温州商学院·国贸 | 467 | 181k | +0.026 | -0.064 | 稳区 |

稳区 8 所里 **4 所是温州商学院**——被 CAP=5 兜住了上限，但问题根源是平滑。

### 修复方案

| 优先级 | 方案 | 改动位置 | 预估影响 |
|---|---|---|---|
| P0 | **对称保护层**：贝叶斯平滑时，若原始位次比先验低 20% 以上（`_ratio < 0.80`），跳过收缩 | `rank_method.py:171` | 低。仅影响小样本冷门专业，预期恢复几十所保底 |
| P1 | **保区兜底回退**：保区 ≤ 5 所时，放宽上界到 +0.60 重新捞 | `recommend_core.py:1695` | 低。仅数据不足时触发 |
| P2 | `_is_low_rank` 门槛微调 | `recommend_core.py:777` | 中。影响所有省份中段考生 |

## 四、算法存废之争（简要）

| 立场 | 核心观点 | 代表声音 |
|---|---|---|
| **守方** | 每条规则都是历史事故的"疤痕组织"，修一条对称保护即可，不应重构 | ECE 0.028 合格、回测基础设施成熟、4-6 周重构无产出 |
| **攻方** | 这是"经验主义补丁堆砌"，三个范式错误（预测值塞硬边界、整校均值做多峰先验、职责耦合不可验证）必须推倒 | 补丁数量单调增长、无 SLA 保证、下一省份必爆新 case |

**实际共识**：
- 眼前最紧迫的修复是 P0（对称保护）+ P1（兜底回退）
- 双方在这个"眼前怎么做"上完全一致
- 分歧只在"做完之后是否立项 v2"
