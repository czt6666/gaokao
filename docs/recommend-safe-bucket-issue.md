# 保底学校推荐过少 —— 诊断与修复方案

## 1. 问题现象

**用户反馈**：浙江考生，分数 480，选科生物+政治+地理，推荐结果里**只有 2 所保底学校**，而且这两所学校的录取分数线和真实分数差距不大（基本贴着 480）。期望看到一些"录取线比真实分数低 10–20 分"的学校（即 460–470 分档）作为保底。

**实测复现**：调用 `_run_recommend_core(province="浙江", rank=194000, subject="生物+政治+地理")` 输出：

| 桶 | 数量 |
|---|---|
| 冲 (surge) | 25 |
| 稳 (stable) | 8 |
| **保 (safe)** | **1**（浙江水利水电学院·国际商务，去年 453 分） |
| 冷门宝藏 (hidden_gems) | 29 |

不是"只有 2 所"，实跑甚至只有 1 所。**数据库里 460–470 分的浙江历史录取数据有几百条，并不缺**。问题出在算法的分桶环节。

---

## 2. 关键背景：分桶是怎么算的

`backend/services/recommend_core.py:1669-1679`：

```python
# gap_rate = (avg_school_rank - student_rank) / student_rank
#   < 0 → 学校更难（冲刺方向）
#   > 0 → 学校更容易（保底方向）
冲 surge:  gap_rate ∈ [-0.20, -0.10)   学校比学生难 10~20%
稳 stable: gap_rate ∈ [-0.10, +0.10]   ±10%
保 safe:   gap_rate ∈ (+0.10, +0.40]   学校比学生容易 10~40%
超出 (>0.40 或 <-0.20) 直接丢弃
```

注意：**这里用的 `avg_school_rank` 是 `avg_min_rank_3yr`——经过加权 + 贝叶斯平滑的预测值，不是历史最低位次的原始平均**。

---

## 3. 根因分析（三层）

### 根因 A：贝叶斯平滑把保区学校误推到稳区（最致命）

`backend/algorithms/rank_method.py:171-176`：

```python
# 当某专业历史数据 ≤3 年，向"学校级先验位次"收缩
# posterior = (n * sample_mean + k * prior) / (n + k)
# k = 2.0，即先验等价于 2 年数据的权重
if school_prior_rank > 0 and len(recent) <= 3:
    _ratio = avg_rank / school_prior_rank
    if _ratio <= 1.8:
        avg_rank = (_n * avg_rank + 2.0 * school_prior_rank) / (_n + 2.0)
```

**`school_prior_rank` 是同一所学校所有专业历史位次的均值**。

这条平滑规则原本是为了"小样本不可靠时向学校均值收缩"，但它在低分段反向起了破坏作用：

| 学校·专业 | 去年实际分 | 去年实际位次 | school_prior（同校均值） | 平滑后 avg_rank | 真实 gap | **平滑后 gap** | 实际归桶 |
|---|---|---|---|---|---|---|---|
| 温州商学院·税收学 | **451** | 212k | ~180k | 186k | **+0.09（保区）** | **-0.038** | ❌ **稳区** |
| 温州商学院·国际经济与贸易 | 467 | 199k | ~180k | 181k | +0.026 | -0.064 | 稳区偏冲 |
| 温州商学院·会计学 | 482 | 185k | ~180k | 176k | -0.046 | -0.091 | 稳区 |
| 浙江水利水电学院·国际商务 | 453 | 210k | ~260k | 245k | +0.083 | +0.263 | ✅ 保区 |

**模式**：当一所学校有少数几个冷门低分专业 + 多数热门正常分专业时，先验位次（同校均值）偏向"难"。冷门专业被平滑后位次被错误地拉高（拉难），gap_rate 从「保区」掉进「稳区」，**用户看不到这些本该作为保底的学校**。

代码 1535-1542 已经做过一次反向修补（防止专科被平滑成本科），但同一种偏差在低分段还是会发生。

### 根因 B：稳区被单一学校垄断

`_SCHOOL_CAP = 5`（`recommend_core.py:1682`）允许同一所学校在同一个桶里出现 5 个专业。

实测稳区 8 所里 **4 所是温州商学院**，占了 50%。原因就是根因 A——温州商学院多个专业被错误地从保区推进稳区，挤掉了多样化的保底名额。

### 根因 C：专科/高职被 SQL 层硬过滤

`recommend_core.py:777`：

```python
_is_low_rank = rank > 0 and _prov_total > 0 and rank > _prov_total * 0.5
if not _is_low_rank:
    _exclude_batch_kw += ("专科", "高职")
```

浙江 2025 总考生 413,000，门槛是 206,500。学生 rank ≈ 194,000，**刚好低于门槛**，所以专科/高职全被 SQL 排除。

对一个 480 分的浙江考生来说，部分优质二段院校 + 头部专科其实是合理的保底层，现在完全看不到。

---

## 4. 为什么 gap_rate 边界（+0.40）本身不是主因

理论上保区 gap_rate ≤ +0.40 对应学校位次 ≤ 272k，约对应录取分 430 分。也就是说**理论上能覆盖到"低 50 分"的学校**。

但因为根因 A，绝大多数 460–470 分档的学校根本到不了分桶这一步——它们的 `avg_min_rank_3yr` 已经被平滑成了"看起来和学生差不多"，gap_rate 落进稳区甚至冲区附近。

所以**放宽 +0.40 边界是治标，修平滑才是治本**。

---

## 5. 修复方案（按推荐优先级）

### 方案 A：贝叶斯平滑加保护层 ★ 推荐

**改动位置**：`backend/algorithms/rank_method.py:171-176`

**思路**：当某专业的原始 `avg_rank` 明显**比同校先验更低（更容易录取）**，说明这是该校的低分冷门专业，向先验收缩反而会失真。应该跳过平滑。

**伪代码**：

```python
if school_prior_rank > 0 and len(recent) <= 3:
    _ratio = avg_rank / school_prior_rank
    # 现有：_ratio > 1.8 时不收缩（防止专科被拉成本科）
    # 新增：_ratio < 0.80 时也不收缩（防止该校低分专业被拉进稳区）
    if 0.80 <= _ratio <= 1.8:
        avg_rank = (_n * avg_rank + 2.0 * school_prior_rank) / (_n + 2.0)
```

**影响**：仅影响"专业实际比学校均值容易 20% 以上"的小样本专业；不动主流路径；预期把根因 A 描述的几十/几百个学校移回保区。

**风险**：低。等效于把现有的单边保护扩成双边对称保护。

---

### 方案 B：保区兜底回退 ★ 推荐

**改动位置**：`backend/services/recommend_core.py:1695-1697` 附近

**思路**：保区最终学校数 ≤ 阈值（比如 5）时，把上界从 +0.40 临时放宽到 +0.60 重新捞，并标注为"扩展保底"。

**伪代码**：

```python
SAFE_MIN = 5
safe_list = _capped_pick(sorted(safe, key=_safe_sort), 25, defaultdict(int))
if len(safe_list) < SAFE_MIN:
    extra = [r for r in results if 0.40 < r["gap_rate"] <= 0.60]
    extra_picked = _capped_pick(sorted(extra, key=_safe_sort),
                                SAFE_MIN - len(safe_list), defaultdict(int))
    for r in extra_picked:
        r["safe_extended"] = True   # 前端可加"扩展保底"小标
    safe_list += extra_picked
```

**影响**：仅在保区匮乏时触发，正常情况不变。

**风险**：低。需要前端配合显示"扩展保底"标识（避免用户误解为高把握保底）。

---

### 方案 C：低位次门槛微调

**改动位置**：`recommend_core.py:777, 837`

**思路**：把 `_prov_total * 0.5` 改成 `* 0.45`，让 47% 段位的考生进入低位次池，引入部分专科作为兜底。

**风险**：中。会影响所有省份的中等偏后段考生，需要重新评估专科混进推荐池是否会污染稳区/冲区。

---

### 方案 D：用去年实际位次重算分桶

**思路**：分桶时优先用 `last_year_min_rank`，3 年均值仅用于趋势判断。

**风险**：高。改动大、需要全链路验证；放弃多年平均会让大小年波动导致分桶不稳定。

---

## 6. 推荐落地步骤

1. **先上 A**（贝叶斯保护层），改 5 行代码，跑一遍同样的浙江 480 用例对比保区数量。
2. **再上 B**（保区兜底回退）作为安全网。两者叠加后再用浙江 480 / 480 之外的几个边界 case（如河南 500、四川 450）验证。
3. C 和 D 暂缓，等 A + B 实测效果不足时再考虑。

## 7. 验证用例

跑完修复后至少验证以下输入，保区学校数应≥ 5：

| 省份 | 分数 | 选科 | 估算 rank |
|---|---|---|---|
| 浙江 | 480 | 生物+政治+地理 | 194,000 |
| 浙江 | 500 | 物理+化学+生物 | 168,000 |
| 河南 | 500 | 理科 | ~160,000 |
| 四川 | 470 | 物理类 | ~150,000 |

每个用例期望：
- 保区 ≥ 5 所
- 保区学校录取分覆盖"学生分数 - 10 分"到"学生分数 - 30 分"范围
- 不同学校占比合理（同一所学校不超过保区的 40%）
