# 推荐算法存废之争 —— 守方 vs 攻方

> 触发：浙江 480 分考生的「保底学校」只剩 1 所。
> 本文是两个独立 agent 对**同一份代码**站在相反立场写出的辩论文档，加上必要的背景与共识总结。
> 读者预设：**没接触过本项目**，但能看懂 markdown 和基本算法术语。

---

## 0. 背景

### 0.1 这个系统是干什么的

「高报」是面向中国高考考生的志愿推荐工具。考生输入「省份 + 位次（或分数）+ 选科」，系统返回一份**冲 / 稳 / 保**三档的院校专业推荐表：

- **冲（surge）**：录取概率较低但有希望，需要点运气
- **稳（stable）**：录取概率高，志愿表里的主力
- **保（safe）**：兜底，几乎必上

中国高考志愿讲究"梯度合理"，三档缺一不可。**保底学校太少 = 志愿表"裸奔"，存在滑档退档风险**——这是触发本次讨论的产品事故。

### 0.2 算法骨架（一段话讲完）

1. **数据源**：`admission_records` 表，每条记录是「某省 × 某校 × 某专业 × 某年」的最低录取分数和位次
2. **预测**：对每个 (school, major)，用最近 5 年的位次做加权平均（近年权重高），如果数据少（≤3 年）再向"同校所有专业的均值"做**贝叶斯平滑**收缩，得到一个 `avg_min_rank_3yr`
3. **分桶**：计算 `gap_rate = (avg_min_rank_3yr - 学生位次) / 学生位次`，用硬阈值切分
   - 冲：[-0.20, -0.10)（学校比学生难 10–20%）
   - 稳：[-0.10, +0.10]（±10%）
   - 保：(+0.10, +0.40]（学校比学生容易 10–40%）
   - 超出范围直接丢弃
4. **排序 + 截断**：每桶按"质量分+冷门价值+机会信号"加权排序，每所学校在同桶里最多 5 个专业（`_SCHOOL_CAP=5`），最终冲 25 + 稳 46 + 保 25 = 96 个名额

### 0.3 用户报告的事故

- **输入**：浙江 / 480 分 / 生物+政治+地理
- **实测**：保底桶 only **1 所**（浙江水利水电学院·国际商务，去年 453 分）
- **期望**：录取分在 460–470 的几十所学校应作为保底
- **诊断**（见 `recommend-safe-bucket-issue.md`）：贝叶斯平滑把多个"该在保区"的低分专业错配进了"稳区"，温州商学院 4 个专业占满稳区 8 个名额中的一半

### 0.4 关键变量速查

| 名字 | 含义 | 出处 |
|---|---|---|
| `min_rank` | 历史录取最低位次（数字越大=越容易上） | DB |
| `school_prior_rank` | 同校所有专业 `min_rank` 的均值（贝叶斯先验） | `rank_method.py:84` |
| `avg_min_rank_3yr` | 加权 + 平滑后的预测位次 | `rank_method.py:302` |
| `gap_rate` | (预测位次 - 学生位次) / 学生位次 | `recommend_core.py:1523` |
| `_is_low_rank` | 学生是否在后半段（rank > 总考生×0.5） | `recommend_core.py:777` |
| `_SCHOOL_CAP` | 同校同桶最多专业数 | `recommend_core.py:1682` |

## 1. 守方陈述（不应推翻）

> 立场：当前的 `predict_admission` + 分桶逻辑是三轮线上事故与回测沉淀下来的均衡解。"浙江 480"案例值得修补一个保护层，但**不构成推翻任何一条核心规则的理由**。

### 设计点 1 · 用 `avg_min_rank_3yr` 做分桶基准

**要解决的真问题**：单年位次受大小年剧烈扰动，是高考志愿领域第一号噪声源。一个 5 人计划的专业去年招到一个偏科尖子，min_rank 能从 8 万跳到 2 万。

**如果换成去年单年位次**：浙江 2023 是物化捆绑改革第二年、2024 又叠加新教材，连续两年都是结构性大小年。仅用去年位次会让冲/稳/保桶在每年 6 月剧烈翻转——去年小年的专业全部跳进保底（其实今年要爆冷回归），去年大年的全部跳进冲刺（其实今年要回落）。**回测 ECE 从 0.028 直接劣化到 0.17 量级**。

**对浙江 480**：攻方自己也承认"放宽 +0.40 边界是治标，修平滑才是治本"——问题出在平滑的边界条件，不是"用均值"本身。

### 设计点 2 · 贝叶斯平滑 + `k_prior=2.0` + 1.8 倍上界保护

**要解决的真问题**：新开/改名专业历史只有 1-2 年数据，方差极大。层级贝叶斯 `posterior = (n·sample + k·prior)/(n+k)` 是统计上最稳健的小样本处理方式，`k=2.0` 让 1 年数据时先验占 67%、3 年时 40%、5 年完全交给样本——这条衰减曲线是回测出来的最优档位。

注释里 1.8 倍上界是为了拦"专科被错误平滑成本科"的反向污染（典型案例：中国民航大学空乘 raw 596k vs 学校先验 147k）。**这条单边保护本身就是一次诊断→修复的产物**。

**对浙江 480**：揭示的是「单边保护不对称」——低分冷门专业被同校均值往难处拉。这是一个可以加上"`_ratio < 0.80` 不收缩"的**对称化补丁**，但这是**对现有保护逻辑的扩展，不是推翻**。补丁的形状与原始设计同构——这恰恰是"现有设计正确"的最强证据。

### 设计点 3 · gap_rate 硬边界 [-0.20, -0.10, +0.10, +0.40]

**要解决的真问题**：志愿表是离散的 96 个槽位，必须给前端一个清晰的三档语义。"冲 10-20%、稳 ±10%、保 10-40%"对应高考填报口语里"够一够、稳稳的、托底"的传统语义。+0.40 上界对应录取分约低 50 分，已足够覆盖正常考生兜底需求。

代码已经为极端情况预留了豁免（rank≤2000 时冲区放宽到 -0.80），**并不需要全面打破边界**。

**对浙江 480**：保区为空不是 +0.40 太严，而是上游候选根本就没掉进保区。修上游平滑后，保区会自然回到 5-10 所，不需要动边界。

### 设计点 4 · `_is_low_rank` 阈值

**要解决的真问题**：本科段（前 50%）考生看到专科会觉得算法掉档、品牌掉价；后 50% 不放行专科则无保底可填。0.5 这个分割线对应大多数省份本专科批次实际录取分位的近似中位。

**如果挪到 0.45**：会让 45%-50% 段（在浙江是 18.5 万-20.6 万位次，**几十万人**）的本科生开始看到专科混入，恰好覆盖产品最敏感的中端用户群。这一段用户对"算法是否专业"的判断完全依赖于"专科不能出现在我的列表里"。

**对浙江 480**：rank 194k vs 门槛 206.5k 确实卡在临界点，但**临界点问题的解法是局部豁免（保区兜底回退），不是全局移动阈值**。

### 设计点 5 · `_SCHOOL_CAP = 5`

**要解决的真问题**：不设上限时，多专业综合性大学会以 15-20 个专业占满整个桶，列表毫无多样性。5 是 A/B 比较的平衡值。

**对浙江 480**："稳区 8 所中 4 所是温州商学院"正是 cap=5 在保护多样性的证据——没有 cap，温州商学院会占满全部 8 个稳区名额。问题是温州商学院**本不该出现在稳区**（这是平滑 bug），修上游后这个症状自然消失。

### 设计点 6-8 · 加权衰减 / 异常年降权 / 缩招分档惩罚

均与浙江 480 案例无关。每一条都对应一个已上线事故的修复（旧政策位次污染、爆冷年误判、缩招专业误导用户）。

### 守方结论：为什么不该重构

1. 浙江 480 案例**只证明了一件事**：贝叶斯平滑的单边保护需要补成双边保护。其他 7 个设计点完全没有被证伪。
2. 注释里出现的"缺陷 1 修复"、"缺陷 2 修复"、"反向兜底"、"P0 校准"、"P4 归一化"——这些**不是冗余，是疤痕组织**，删一条等于把一次历史事故的修复也删掉。
3. 最佳路径是**加保护层而不是换地基**：把 `if _ratio <= 1.8` 改成 `if 0.80 <= _ratio <= 1.8`，配合保区兜底回退，改动 10 行以内即可恢复 ≥ 5 所保底。
4. 整体推翻的代价：ECE 校准曲线（19.2 万条数据训练）、ARIMA 大小年模型、population 归一化、校准器训练流程，全部要重新跑——上线至少 4-6 周，期间无可用算法。**ROI 不成立**。

## 2. 攻方陈述（必须推翻）

> 立场：这套设计是**经验主义补丁的堆砌**，缺少统一的统计模型与显式可调的产品语义。浙江 480 暴露的不是 bug，是**架构性失败**——保区只剩 1 所是这套设计的必然产物，不是参数没调好。

### 问题 1 · 拿"预测值"当"硬边界"是范畴错误

`gap_rate` 的分子是一个经过 5 重加工（跨年归一化 → 加权 → 异常年降权 → 贝叶斯平滑 → 缩招惩罚）的合成预测值，再被丢进 ±0.10 / +0.40 的确定性硬阈值里。

硬边界**要么用事实**（去年实际位次），**要么用带不确定性的分布**（后验+置信区间），**绝对不能用一个未标方差的点估计**。`predict_admission` 同时返回 `prob_low/prob_high`，但分桶环节把这两个字段彻底丢掉——**置信区间算了没用**。

**失败泛化**：任何一个"原始位次接近分桶边界、且被平滑轻微扰动"的学校都会在桶之间随机跳变。换河南理科 500、新高考 3+1+2 任意组合同样成立。

**v2 思路**：分桶基准必须用**单一、可解释、不可被中间步骤污染**的量。两个选择：(1) 直接用 `last_year_min_rank`；(2) 用**概率本身**分桶——例如"录取概率 ∈ [20%, 50%) 冲 / [50%, 85%) 稳 / [85%, 99%] 保"。

### 问题 2 · 贝叶斯先验是混合分布均值——系统性污染

`school_prior_rank = 同校所有专业历史位次的均值`。但**同一所学校的专业位次分布通常是双峰甚至多峰的**（计算机/金融在一端、农林/思政/小语种在另一端）。用混合分布的均值当先验，等于假设所有专业服从同一个单峰分布——**统计上完全站不住脚**。

**失败泛化**：不是浙江一个案例。任何"综合性大学的冷门专业"都会被向校均值收缩。换到 985 综合大学的护理、马克思主义理论，同样会被校先验系统性高估——**专业越冷门，错得越离谱**。

**v2 思路**：(1) 先验粒度下沉——按"学校 × 学科门类"分组；(2) 改用**经验贝叶斯**，先验从"同类专业全国分布"估；(3) 收缩前做**先验适用性检验**，不适用就拒绝收缩。

### 问题 3 · gap_rate 硬边界没有统计学依据

四个数字哪来的？**没有任何回测、没有任何省份/位次段分层**。+0.40 在高分段（rank=2000）对应位次差 800，在中低分段（rank=200,000）对应位次差 80,000——**同一组数字在不同分位上代表的"风险距离"差 100 倍**。

更糟的是没有"保底宽松度"显式参数——运营想把保底放宽只能改源码。

**失败泛化**：每个边缘场景都需要单独打补丁（`rank<=2000` 的 `_SURGE_LO=-0.80`、浙江 480 的"保区空了"）。换 3+1+2 省份、艺术体育、提前批，每一类都得新增 if 分支。

**v2 思路**：(1) 边界**随位次密度自适应**；(2) "保底宽松度"提到 API 层成显式参数；(3) 边界值必须有**回测脚本固化**——以"用户次年实际去向的录取概率分布"作为 ground truth。

### 问题 4 · `_is_low_rank` 用半数门槛是因果倒置

把"是否在后半段"等同于"是否需要看专科"，但**位次和专科适配性之间没有因果链**。浙江 480 学生差 12,500 名就被一刀切掉所有专科——本科线划在哪、考生本人是否愿意接受专科、当年扩招缩招，**和 50% 这个数字毫无关系**。

**v2 思路**：批次决策不该用"位次百分位"，而该用**"本科线/特控线相对距离"**——如果考生分数距离本科线 < 30 分，自动把头部专科作为候补保底，由用户在 UI 上勾选是否接受。**门槛逻辑应该软化、可配置、对用户透明**。

### 问题 5 · `_SCHOOL_CAP=5` 治标不治本

CAP 只是把症状从"8 所里 5 所同名"压到"8 所里 4 所同名"。**真正根因是问题 2 的先验污染把同一所学校的多个专业一起错配进同一桶**。

反向伤害：本来该出现在保区的多样性候选被 CAP 提前淘汰，因为排序低于被错配进来的"同校冷门专业"。

**v2 思路**：多样性应该是**排序目标函数**里的一项（最大边际相关性 MMR），而不是 post-hoc 截断。

### 问题 6 · `predict_admission` 职责耦合到无法验证

一个函数同时做：跨年归一化、异常年检测、加权平均、贝叶斯平滑、sigmoid 概率、P0 校准、CV 高波动收缩、置信区间、ARIMA 大小年、缩招分档惩罚。**任何一步出问题，你不知道是哪一步**。

`avg_min_rank_3yr` 这个字段在贝叶斯平滑后被覆盖（`rank_method.py:176`），但下游仍当作"3 年均值"使用——**命名和语义已经脱钩**。

**v2 思路**：拆成**单一职责的纯函数 pipeline**——`normalize_ranks` → `detect_anomaly` → `fit_posterior` → `apply_plan_penalty` → `calibrate`。每一步输入输出都有 schema、有单元测试。点估计字段必须改名（`smoothed_rank` 而非 `avg_min_rank_3yr`），让下游用错时类型检查就报错。

### 问题 7 · 补丁叠补丁是技术债的临床体征

`rank_method.py:173` 的 `_ratio <= 1.8` 防"专科被拉成本科"；`recommend_core.py:1538` 的 `_last_year_gap_rate > 0.55` 再防"贝叶斯平滑把专科漏过来"。**两条补丁防的是同一个 bug**，发生在不同层级——典型的「在错误的抽象层修问题」反模式。

诊断报告还要再加 `_ratio < 0.80` 对称保护——**补到第三条，没人能在脑子里同时持有这些规则的交互效应**。

**v2 思路**：把"专科/二段/提前批不该被本科推荐"提升到**类型系统层级**——`AdmissionRecord` 带 `batch_tier` 枚举，建模与推荐严格按 tier 分流，**根本不让两类数据在同一个均值里出现**。补丁消失，因为脏数据进不来。

### 问题 8 · 没有"保区最小数量"保证——没有自救机制

现行流程是**单向漏斗**——SQL 过滤 → 分桶 → 截断 → 输出。**任何一步把保区掏空，输出就是 0**。

**失败泛化**：边远省份、艺术类、改名学校、新增专业、新高考首年——都会触发。**用户拿到一份"不完整的志愿表"还以为是最佳答案，比报错更危险**。

**v2 思路**：推荐输出必须有 **SLA 约束**——「冲 ≥ X、稳 ≥ Y、保 ≥ Z」是硬契约，不满足就触发显式回退链（放宽 gap_rate → 放宽批次 → 跨省同类参考 → 提示用户）。

### 攻方结论：为什么必须重构

这套算法的问题不是"某一处写错了"，而是**三个根本性范式错误叠加**：

1. **把不确定性塞进硬边界**——预测值（带方差）当阈值（无方差）用
2. **统计模型选错抽象层级**——整校均值做单峰先验、位次百分位做批次门槛、魔法常数（1.8 / 0.55 / 0.80 / 5）打补丁
3. **职责耦合到无法验证**——`predict_admission` 一个函数 10 个职责、分桶链路无 SLA 无回退

继续打补丁的代价已经清晰可见：诊断报告里的方案 A/B/C/D 四条全部是「在错的层再加一条 if」。修了浙江 480，下一个省份就会再爆。

## 3. 共识与分歧

### 双方实际同意的事

| 共识点 | 双方表述 |
|---|---|
| 浙江 480 案例的**直接症结**在贝叶斯平滑（设计点 2 / 问题 2） | 守方："单边保护需要补成双边"；攻方："先验是混合分布均值，对低分专业污染" |
| `_SCHOOL_CAP=5` 在本案例中**没出错**，只是放大了上游 bug 的可见度 | 守方："修上游后症状自然消失"；攻方："CAP 只是把症状从 5/8 压到 4/8" |
| 现行代码里有**多处反向补丁**（1.8 阈值、0.55 兜底） | 守方："疤痕组织，每一条都对应一次事故"；攻方："补丁叠补丁，技术债临床体征" |
| 浙江 480 案例**自身只能小修**，5–10 行能让保区回到 ≥5 所 | 守方："这恰是不该重构的证据"；攻方："这恰是已经无路可走的证据" |

### 双方真正分歧

**这些"反向补丁"是疤痕组织（守方）还是溃疡前兆（攻方）？**

- 守方视角：每一条补丁都对应一次真实事故，删除等于回到事故前。补丁的"形状"与原设计**同构**，说明结构正确。
- 攻方视角：补丁数量在单调增长，且总是"在错的层"加，说明结构本身让 bug 不断在抽象的不同层重现。再加 3 条补丁后没人能推理交互效应。

**"统计上正确"和"工程上够用"哪个优先？**

- 守方：现有算法 ECE 0.028（19.2 万条训练数据），实际录取概率校准合格。理论瑕疵不影响线上指标。
- 攻方：ECE 是全局指标，**掩盖了局部失效**（特定省份/分段的桶内组成）。线上事故是从局部开始的，不会先在全局指标上预警。

### 第三种声音（本文作者补充）

两份文档其实指向**同一个核心事实**：当前最紧迫的修复点就是贝叶斯平滑的对称保护 + 保区兜底回退。两个 agent 在"该怎么做眼前这件事"上完全一致，分歧只在"做完这件事之后"：

- 守方说：做完就停，剩下的设计点别动
- 攻方说：做完只是续命，应该启动 v2 立项

**这是一个组织决策、不是技术决策**——取决于团队现在是否有人力/时间窗口启动 v2，以及对"未来 6 个月内会不会爆出新的边缘 case"的风险偏好。

| 维度 | 守方 | 攻方 |
