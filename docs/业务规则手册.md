# 业务规则手册

> 本文档汇总选科匹配、专业限制、产品档位、定价与竞品等业务规则。

## 一、选科匹配规则

系统识别三种高考模式，分别走不同逻辑：

### 3+1+2 模式（23 省）

- **首选科目池过滤**：物理生排除 `历史类/文科/历史`，历史生排除 `物理类/理科/物理` + 全国仅招物理专业
- **再选科目 AND/OR 匹配**：
  - `subject_must`：必须全含（如 "物理,化学" → 考生必须有物+化）
  - `subject_any_of`：满足其一即可（如 "化学/生物" → 考生有化或有生即可）
- 保留原始选科要求，不简化为"物理类"，避免"物+生"考生被误推"物+化"专业

### 3+3 模式（6 省：浙江、上海、北京、天津、山东、海南）

- 纯科目集合匹配，无首选/再选之分
- 专业要求科目 ⊆ 用户选科，即视为可报

### 旧高考（新疆、西藏）

- 只看科类（理科/文科）
- 理科排除"历史类/文科"标识，文科排除"物理类/理科"标识

## 二、专业限制过滤

`admission_records.major_restrictions` 字段记录的身体/条件限制，SQL 层硬过滤：

| 限制类型 | 示例 | 过滤逻辑 |
|----------|------|---------|
| 性别限制 | "只招男生"、"只招女生" | 按考生性别排除 |
| 视力限制 | "不招色盲"、"不招色弱" | 按考生填报的身体条件排除 |
| 语种限制 | "只招英语考生" | 按外语语种排除 |
| 身高/其他 | "男生≥170cm" | 按考生填报信息排除 |

> 考生需在查询表单中如实填报身体条件，系统据此过滤不可报专业。

## 三、概率档位定义

| 档位 | 概率范围 | 标签 | 含义 |
|------|---------|------|------|
| 极冲 | 10% ≤ p < 25% | `极冲` | 历史上偶有录取，概率低但值得列出 |
| 冲 | 25% ≤ p < 55% | `冲` | 有竞争性但存在风险 |
| 稳 | 55% ≤ p < 82% | `稳` | 主力志愿区间 |
| 保 | p ≥ 82% | `保` | 兜底志愿 |

**特殊规则**：
- 高位次考生（rank ≤ 2000）冲区允许低至 10%，避免顶尖高校被截断
- 所有结果 p < 10% → 取最高 30 条标"参考"填入 safe 桶
- combined_96 ≥ 1 但 < 30 → 补齐至 30 条标"参考"

## 四、报告数量目标

- **目标 96 所**：冲 25 + 稳 46 + 保 25
- 每所学校最多 5 个专业跨桶共享（`_SCHOOL_CAP = 5`）
- 正常数据省份必须 ≥ 30 所，否则自动补"参考"

## 八、待评审改造

### 专业筛选改造（2026-05-17 提案）

**现状**：专业筛选用关键词文本匹配（如输入"计算机"匹配所有含"计算机"的专业名）。

**问题**：
- 用户不知道专业名的完整写法（如"计算机科学与技术"）
- 同一大类下专业分散，难以整体浏览

**提案**：改为「门类 → 大类 → 专业」三级树形筛选：
- 第一级：工学 / 理学 / 经济学 / 医学…
- 第二级：计算机类 / 电子信息类 / 机械类…
- 第三级：具体专业（可多选）

**状态**：待评审，未实施。影响范围：前端表单（网页+小程序）、后端 `/api/recommend`、数据库需新增字典表、PDF 报告参数。
